Você receberá:

1. Um PDF de uma prova de vestibular.
2. Opcionalmente, um PDF de gabarito.
3. Um arquivo taxonomia.json contendo a taxonomia atual.

Sua tarefa é gerar dois arquivos para download:

1. prova.json
2. taxonomia.json atualizado

OBJETIVO

Construir uma base de dados estruturada de vestibulares, permitindo:

- estatísticas por disciplina;
- estatísticas por assunto;
- estatísticas por subassunto;
- estatísticas por tópico;
- análise histórica da incidência de conteúdos;
- reclassificação futura sem perda de informação.

REGRAS GERAIS

- Analise todas as questões da prova.
- Utilize a taxonomia existente sempre que possível.
- Considere a estrutura existente da taxonomia como imutável.
- Não remova itens existentes da taxonomia.
- Não altere IDs existentes.
- Não renomeie IDs existentes.
- Não altere nomes existentes.
- Não altere níveis existentes.
- Não altere sinônimos existentes.
- Não modifique a hierarquia existente.
- Não reordene nós existentes.
- Não aplique ordenação alfabética na taxonomia.
- Não mova nós existentes para outra posição.
- Não crie categorias redundantes.
- Antes de criar um novo item, verifique se já existe um equivalente semântico.
- Quando for necessário criar um novo item, adicione-o diretamente ao taxonomia.json.
- Novos itens devem ser adicionados exclusivamente ao final da lista `filhos` do nó pai correspondente.
- Se múltiplos itens forem adicionados ao mesmo pai, mantenha a ordem em que foram identificados durante a análise.
- Preserve ao máximo a estrutura original do arquivo para minimizar alterações em diffs de Git.
- Em um diff, idealmente apenas novas linhas devem aparecer adicionadas.
- Todo taxonomiaId utilizado em prova.json deve existir no taxonomia.json final.
- O JSON gerado deve ser válido.

================================================================================
ESTRUTURA DE taxonomia.json
================================================================================

A taxonomia é recursiva.

Cada nó possui:

{
  "id": "string",
  "nome": "string",
  "nivel": "disciplina|assunto|subassunto|topico",
  "sinonimos": [],
  "filhos": []
}

Exemplo:

{
  "id": "biologia",
  "nome": "Biologia",
  "nivel": "disciplina",
  "sinonimos": [],
  "filhos": [
    {
      "id": "biologia_fisiologia_humana",
      "nome": "Fisiologia humana",
      "nivel": "assunto",
      "sinonimos": [],
      "filhos": [
        {
          "id": "biologia_fisiologia_humana_sistema_digestorio",
          "nome": "Sistema digestório",
          "nivel": "subassunto",
          "sinonimos": [],
          "filhos": [
            {
              "id": "biologia_fisiologia_humana_sistema_digestorio_pancreas_exocrino",
              "nome": "Pâncreas exócrino",
              "nivel": "topico",
              "sinonimos": [
                "Função exócrina do pâncreas",
                "Secreção pancreática"
              ],
              "filhos": []
            }
          ]
        }
      ]
    }
  ]
}

REGRAS PARA A TAXONOMIA

- IDs devem ser estáveis.
- IDs devem ser minúsculos.
- IDs não devem possuir acentos.
- IDs devem usar underscore (_).
- IDs devem refletir a hierarquia.
- Não utilizar espaços.
- Não utilizar caracteres especiais.
- Não criar dois nós equivalentes semanticamente.
- Utilizar sinonimos para registrar nomenclaturas alternativas.
- Sempre preencher filhos com uma lista, mesmo que vazia.

================================================================================
ESTRUTURA DE prova.json
================================================================================

{
  "prova": {
    "questoes": [
      {
        "numero": 1,
        "pagina": 1,
        "gabarito": "A",
        "taxonomiaId": "string",
        "contexto": [],
        "comando": "string",
        "alternativas": {
          "A": "string",
          "B": "string",
          "C": "string",
          "D": "string",
          "E": "string"
        }
      }
    ]
  }
}

================================================================================
REGRAS PARA QUESTÕES
================================================================================

Cada questão deve possuir:

- numero
- pagina
- taxonomiaId
- contexto
- comando
- alternativas

O campo gabarito deve corresponder exatamente ao gabarito oficial.

================================================================================
SEPARAÇÃO ENTRE CONTEXTO E COMANDO
================================================================================

O campo contexto deve conter todo material necessário para resolver a questão.

Exemplos:

- texto-base;
- tirinhas;
- gráficos;
- mapas;
- fotografias;
- tabelas;
- diagramas;
- esquemas;
- imagens.

O campo comando deve conter exclusivamente a pergunta ou instrução principal da questão.

Exemplo:

Contexto:

"A televisão já foi vista como o fim do cinema..."

Comando:

"Dentro da perspectiva apresentada pelo autor, a Inteligência Artificial vai"

================================================================================
FORMATO DE CONTEXTO
================================================================================

O campo contexto deve conter todo o material necessário para resolver a questão.

Cada questão deve ser completamente independente. Portanto, todo texto, imagem ou elemento visual necessário para sua resolução deve estar presente em seu próprio contexto, mesmo que esse mesmo conteúdo seja compartilhado por outras questões da prova.

O campo contexto é uma lista ordenada.

Regras:

- Preserve a ordem original dos elementos conforme aparecem na prova.
- Cada elemento deve ocupar uma posição própria na lista.
- Não combine múltiplos elementos em um único item de contexto.
- Não agrupe textos distintos em um único item.
- Não agrupe múltiplas imagens em um único item.
- Se uma questão depender de dois gráficos, eles devem ser representados por dois itens distintos.
- Se uma questão depender de um texto e de uma imagem, eles devem ser representados por dois itens distintos.
- Se um mesmo texto ou elemento visual for utilizado por múltiplas questões, ele deve ser repetido em cada uma delas.

Formato de cada item:

{
  "tipo": "texto",
  "conteudo": "..."
}

ou

{
  "tipo": "imagem",
  "mimeType": "image/png",
  "conteudo": "base64..."
}

Tipos permitidos:

- texto
- imagem

Representação:

- Conteúdo puramente textual deve ser armazenado como tipo "texto".
- Qualquer elemento visual deve ser armazenado como tipo "imagem".

Elementos visuais incluem, mas não se limitam a:

- tirinhas;
- fotografias;
- gráficos;
- mapas;
- tabelas;
- diagramas;
- esquemas;
- infográficos;
- ilustrações;
- capturas de tela;
- figuras.

Imagens devem ser armazenadas em base64.

Princípio de preservação:

O contexto deve preservar fielmente todas as informações necessárias para que um humano ou outro modelo consiga resolver a questão sem consultar o PDF original.

================================================================================
CLASSIFICAÇÃO
================================================================================

Escolha o taxonomiaId mais específico possível.

Exemplo ruim:

biologia

Exemplo melhor:

biologia_fisiologia_humana

Exemplo ideal:

biologia_fisiologia_humana_sistema_digestorio_pancreas_exocrino

Priorize sempre o nível mais profundo aplicável.

================================================================================
VALIDAÇÃO FINAL
================================================================================

Antes de finalizar:

- Verifique se todas as questões da prova foram extraídas.
- Verifique se todas as alternativas foram extraídas.
- Verifique se todas as imagens relevantes foram incluídas.
- Verifique se todos os textos-base foram incluídos.
- Verifique se todos os taxonomiaId utilizados existem no taxonomia.json final.
- Verifique se o gabarito coincide com o gabarito oficial quando disponível.
- Verifique se os dois arquivos são JSON válido.

Saída esperada:

- Arquivo para download: prova.json
- Arquivo para download: taxonomia.json atualizado
